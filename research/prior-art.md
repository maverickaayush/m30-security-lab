## Flipper and auxiliary interfaces

Official [Flipper hardware specs](https://docs.flipper.net/zero/development/hardware/tech-specs)
list BLE 5.4, CC1101 sub-GHz, ST25R3916 NFC, 125 kHz RFID, infrared,
GPIO and USB. Its [Bad USB guide](https://docs.flipper.net/zero/bad-usb)
documents USB/BLE HID. [Wi-Fi developer board schematics](https://docs.flipper.net/zero/development/hardware/devboard-schematics)
show Wi-Fi on an external ESP32-S2 module. These hardware components are not
created by an M30 app, root shell, chroot or Linux BlueZ port.

## Source and issue-tracker boundaries

The public M30-family repository's current HEAD is `0952065`, advertises GCC
4.9 and `m30lte_00_defconfig`, and showed zero GitHub Issues at inspection.
The [TeamWin M30 device tree](https://github.com/TeamWin/android_device_samsung_m30lte)
links that kernel but does not validate this running recovery. Official
[Samsung OSRC](https://opensource.samsung.com/) remains the required exact
source provider. The inspected [REA repo](https://github.com/morluto/rea)
current HEAD is `1173c0a9dc1b352a60943a491462294db8f353ae`; its presence
as a tool is not prior evidence of M30 firmware support. No maintained bridge
or completed SCSC BlueZ port on this exact build was established by this
search, which is a scoped search result rather than a nonexistence proof.
